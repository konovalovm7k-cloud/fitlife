# Анализ питания по фото: план и критерии готовности

## Решение

Актуальный путь V2: модель возвращает только названия, предполагаемые граммы и
коды неопределённости. Пользователь выбирает источник состава; Nutrition Engine
считает КБЖУ перед явным подтверждением. Описание V1 ниже сохранено как история
первой реализации, оно не означает разрешения брать нутриенты из модели в V2.
Контроль разных публичных снимков и его ограничения описаны в
[PHOTO_CASE_ACCEPTANCE.md](PHOTO_CASE_ACCEPTANCE.md).

Flutter -> HTTPS Cloudflare Worker -> Google Gemini. Общий сервер для нескольких
пользователей; ключ Google только в Worker Secret. Дневник остаётся локальным,
совместимым с существующими данными. Никакой автоматической записи результатов.

## Этапы

1. Сохранить существующую архитектуру и проверить базовые analyze/test/release.
2. Добавить независимый модуль photo_analysis: строгий контракт, HTTP-клиент,
   таймауты, безопасное хранение адреса и индивидуального кода доступа.
3. Подготовить JPEG на телефоне: уменьшить размер, применить ориентацию,
   удалить EXIF/GPS. Фото передаётся только по явному согласию пользователя.
4. Реализовать Worker с Gemini structured output, проверкой ответа и ограничением
   размера запроса. Без хранения фото, журналирования токенов и ответов модели.
5. Реализовать D1: хеши индивидуальных токенов, отзыв доступа, атомарное резервирование
   квоты пользователя/сервера, ограничение запросов в минуту и защита от повторов.
   Ошибки Google также расходуют резерв: автоматических повторов и платного fallback нет.
6. Добавить экран проверки: блюда, граммы, КБЖУ/клетчатка на 100 г, уверенность,
   предупреждения; редактирование, удаление, добавление пропущенного ингредиента.
   Итоги пересчитываются из подтверждённых данных, а не берутся из текста модели.
7. Сохранять весь подтверждённый приём пищи одной операцией в выбранную дату.
   Ошибка записи не закрывает экран, повторное нажатие не создаёт дубликаты.
8. Проверить контракты, авторизацию, квоты, ошибки сети/модели, отказ от отправки,
   правку порций, сохранение и повтор. Добавить серверные проверки в Actions.
9. Собрать подписанный APK, запустить native release smoke, выдать артефакт.
10. Подключить аккаунты владельца, развернуть Worker/D1, выдать отдельные коды,
    проверить реальное распознавание и доступность сервера на телефоне.

## Ограничения и приватность

- Это оценка, не лабораторное измерение и не медицинская рекомендация.
- Нутриенты относятся к состоянию блюда на фото (готовое/сырое), а не к случайному
  совпадению названия во встроенном каталоге. Не выдавать AI-оценки за данные USDA.
- Бесплатные тарифы имеют квоты и региональные ограничения. Использовать проект
  Google без подключённого биллинга и Workers Free. Код не может запретить владельцу
  впоследствии включить платный тариф в консоли провайдера.
- На бесплатном уровне Google может использовать контент для улучшения продуктов.
  Это должно быть явно указано до отправки. Не отправлять фото людей/документов.
- Сервер хранит только хеши доступа и технические счётчики запросов; не дневник и фото.
- Без аккаунтов/ключа/публичного URL можно проверить код и тестовый контракт, но нельзя
  честно объявить облачную функцию активированной или подтвердить качество Gemini.

## Приёмка

- flutter analyze, flutter test, server tests, release APK build проходят.
- Старый дневник читается; ручной ввод, навигация и восстановление запуска сохранены.
- Нет ключа Gemini в исходниках/APK, нет публичного неавторизованного AI-прокси.
- Ошибки имеют конечный таймаут и понятное действие, а не вечное колесо загрузки.
- Реальная облачная проверка отдельно от тестов с подставным ответом провайдера.
