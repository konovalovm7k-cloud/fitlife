# Как включить распознавание по фото в FitLife

Приложение и сервер подготовлены в коде. Для настоящего распознавания нужно один
раз запустить сервер в ваших аккаунтах. После этого все пользователи подключаются
к одному адресу, каждый со своим кодом. Пересобирать APK для смены адреса не нужно.

## 1. Google AI Studio

1. Откройте [Google AI Studio](https://aistudio.google.com/), войдите через Google.
2. Проверьте [доступность в вашей стране](https://ai.google.dev/gemini-api/docs/available-regions).
   Доступ зависит от региона, возраста и подтверждения аккаунта. Если сервис не
   доступен, сначала потребуется выбрать другого доступного провайдера.
3. Создайте проект и API key в разделе API keys. Выберите бесплатный уровень,
   не подключайте платёжный аккаунт. Ключ не присылайте в чат и не добавляйте в GitHub.
4. Проверьте доступность модели `gemini-3.8-flash` и её квоты в проекте.
   Название настраивается через `GEMINI_MODEL` в `wrangler.toml`.

[Google указывает бесплатный ввод и вывод для этой модели](https://ai.google.dev/gemini-api/docs/pricing),
но квоты ограничены и могут меняться. При исчерпании лимита FitLife показывает
ошибку; платная модель автоматически не включается. На бесплатном уровне Google
может использовать переданный контент для улучшения продуктов. Пользователь
видит это до отправки снимка.

## 2. Cloudflare

1. Зарегистрируйтесь на [Cloudflare](https://dash.cloudflare.com/sign-up), подтвердите email.
2. Используйте Workers Free. Покупать домен не нужно: подойдёт адрес `workers.dev`.
3. На компьютере нужны Node.js 24 и pnpm 11.25.0. Откройте терминал в папке
   `server` этого репозитория и выполните:

```powershell
npm install --global pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm exec wrangler login
pnpm exec wrangler d1 create fitlife-photo
```

В браузере подтвердите вход Cloudflare. Последняя команда выдаст `database_id`.
Укажите его вместо `REPLACE_WITH_D1_DATABASE_ID` в `server/wrangler.toml`.
Это идентификатор базы, а не секретный ключ.

```powershell
pnpm exec wrangler d1 migrations apply fitlife-photo --remote
pnpm exec wrangler deploy
pnpm exec wrangler secret put GEMINI_API_KEY
```

При запросе секрета вставьте ключ Google в терминал. Он хранится в Worker Secret,
не в исходниках и не в APK. Запишите HTTPS-адрес, выданный `deploy`.
На этом этапе `/health` возвращает статус самого сервера, но не проверяет ключ Google.

## 3. Выдать доступ пользователям

Для первого пользователя (например, `owner`):

```powershell
node tools/invite.mjs owner
pnpm exec wrangler d1 execute fitlife-photo --remote --file private/owner.sql
```

Индивидуальный код появится в `server/private/owner.txt`. В базу попадает только
SHA-256 хеш. Папка `private` исключена из Git. Передайте адрес сервера и код
лично нужному человеку, не публикуйте их в общем репозитории.
Для следующего человека используйте другое имя (`user-2` и т. п.).

Отозвать доступ:

```powershell
pnpm exec wrangler d1 execute fitlife-photo --remote --command "UPDATE users SET enabled = 0 WHERE id = 'owner'"
```

Для замены кода отзовите старый доступ и создайте нового пользователя с другим именем.
Коды служат приглашениями для небольшой группы: самостоятельной регистрации и
восстановления учётной записи в этой версии нет.

## 4. Подключить телефон

1. Установите APK FitLife 4.4.0 поверх предыдущей версии.
2. Откройте «Камера» -> «Подключить сервер распознавания».
3. Введите HTTPS-адрес без `/v1/analyze` и личный код из 43 символов.
4. Выберите фото блюда, нажмите «Оценить калорийность» и подтвердите отправку.
5. Исправьте состав, вес и КБЖУ при необходимости, выберите приём пищи и сохраните.

## Лимиты и хранение

Начальные ограничения в `wrangler.toml`: 10 запросов на пользователя в сутки,
100 на весь сервер в сутки и 5 в минуту на весь сервер. Дни считаются по UTC.
Настройте их не выше реальных квот вашего Google-проекта и повторите `wrangler deploy`.
Ошибки распознавания тоже используют резерв; автоматических повторов нет.

Фото уменьшается на телефоне до 1280 пикселей по длинной стороне, EXIF/GPS
удаляются; запрос не превышает 512 КБ. Сервер не сохраняет фото, результаты
распознавания и дневник. Технические записи (ID пользователя, ID запроса, время)
удаляются планировщиком через 30 дней. Коды в телефоне хранятся защищённо и
исключены из резервного копирования Android. Записи дневника остаются локальными.

Workers/D1 Free также имеют [собственные лимиты](https://developers.cloudflare.com/workers/platform/limits/).
Бесплатные планы рассчитаны на небольшую группу. Большое публичное приложение
потребует отдельного планирования квот, регистрации пользователей и эксплуатации.

## Проверка перед выдачей пользователям

```powershell
node --test
pnpm exec wrangler deploy --dry-run --outdir dist/worker
```

Тесты используют подставной ответ Google и локальный Workers runtime/D1.
Они не проверяют качество реального Gemini. После настройки аккаунтов проверьте
реальное фото, отсутствие еды на фото, исчерпание квоты и отзыв кода.

Если появляется ошибка подключения, проверьте HTTPS-адрес и доступность
`https://ВАШ-АДРЕС/health` с телефона. При 401 проверьте код; при 429 подождите
сброса квоты; при 502/503 проверьте Worker Secret и доступность модели в AI Studio.
Проверяйте метрики без записи тел запросов, фото и заголовков авторизации.

Официальные инструкции: [D1](https://developers.cloudflare.com/d1/get-started/),
[Worker Secrets](https://developers.cloudflare.com/workers/configuration/secrets/).
