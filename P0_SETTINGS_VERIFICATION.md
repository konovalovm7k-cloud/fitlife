# P0.2: надёжное сохранение настроек FitLife

21 октября 2026 года. Версия приложения: **4.4.1+11**.

Основа: `a12e7e3` из [PR #3](https://github.com/konovalovm7k-cloud/fitlife/pull/3).
На момент начала этапа PR #3 и PR #2 открыты, `main` остаётся на `2e0e210`.
Продолжение подготовлено отдельной веткой `codex/p0-settings-integrity`.

## Реализовано

- Все изменения дневника и настроек используют одну очередь с перечитыванием
  SharedPreferences перед операцией. Значения `false` и исключения записи
  становятся ошибкой, а оптимистический кэш после ошибки перечитывается.
- Калории, белки, жиры и клетчатка сохраняются одним версионированным JSON-снимком
  `nutrition_goals_v1`. Четыре старых ключа читаются при первой миграции и
  сохраняются на устройстве. После миграции источником норм служит снимок.
- Вода прибавляется к подтверждённому значению выбранного дня. Быстрые нажатия
  последовательно учитываются без потери прибавок. При ошибке экран не показывает
  несохранённый результат.
- Миграция старого счётчика воды сначала записывает значение сегодняшнего дня,
  затем маркер. Отказ любого шага допускает повтор без удвоения. Историческая
  дата не получает недатированное значение старого счётчика.
- Избранное изменяется после успешной записи. При ошибке звёздочка остаётся
  в подтверждённом состоянии, сообщение позволяет повторить действие.
- Свои продукты и продукты расширенного каталога сохраняются через один
  репозиторий с объединением по стабильному ID. Повтор не создаёт дубликат
  и не удаляет другие продукты.
- Формы своих продуктов, целей и текущего веса остаются открытыми при ошибке,
  сохраняют введённые значения и разрешают повтор. Пока идёт запись, повторное
  сохранение, отмена и системный Back блокируются. Чтение и запись веса
  сохранены; история веса относится к последующему этапу P1.
- Последние продукты сохраняются отдельно от избранного. Если обновить этот
  список не удалось после записи еды, приложение сообщает, что еда сохранена,
  закрывает форму и не предлагает повторно добавлять уже записанный приём пищи.
- Разные повреждённые версии данных сохраняются в отдельных recovery-копиях.
  Старые NaN/Infinity сохраняются в копии как явно обозначенные ошибочные числа.
  Если копию записать не удалось, исходные повреждённые данные не заменяются.

## Проверки

Проверяются успешное сохранение и восстановление после перезапуска, отказы
и исключения диска, миграции старых ключей, дробные значения, конкуренция
дневника/настроек, повторные нажатия, сохранение черновиков и блокировка Back
на время записи. Старые тесты дневника, каталога, навигации, фото и расчётов
сохраняются.

Команды проверки:

```text
flutter analyze --no-pub
flutter test --no-pub
flutter build apk --release --no-pub --android-project-arg=kotlin.incremental=false
```

Флаг Kotlin используется только для локальной Windows-сборки с SDK на другом
диске. GitHub Actions собирает APK штатной командой без этого флага.
Release smoke-тест дополнен записью четырёх целей и проверкой всего снимка
после холодного запуска на Android-эмуляторе.

Локальные результаты: `flutter analyze` — без замечаний; `flutter test` —
70 тестов успешно (17 новых сценариев второго этапа); release APK 4.4.1+11
собран, 56.1 MB; `git diff --check` — успешно; Python smoke-скрипт компилируется.
Локальная сборка проверяет release-код со стандартной debug-подписью.
Для передачи пользователю используется облачный APK с проверкой release-подписи.

Финальные результаты, ссылка на запуск Actions и контрольная сумма облачного
APK фиксируются в описании PR после завершения проверок.

## Следующий этап

P0.3 — дальнейшее выделение контроллера состояния из активной оболочки и
согласование production entry point без удаления старых функций.
P0.4 — единый расчёт норм и проверка энергетической согласованности.
Рецепты, индивидуальный профиль, история веса, тренды, копирование дня,
резервные копии и техническая оценка штрихкодов остаются в очереди P1–P2.

SharedPreferences не даёт полной транзакционности нескольких ключей и гарантий
при аварийном отключении питания. Единая запись снимка исключает частично
обновлённые цели на уровне приложения. Очередь работает в одном isolate.
Физический телефон в этом этапе отдельно не проверялся.
