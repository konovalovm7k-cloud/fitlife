# Воспроизводимая проверка публичных фото

`tool/check_photo_cases.py` проверяет три закреплённых снимка: яблоко, банан и
смешанную тарелку с рисом/фасолью. Это небольшие контрольные случаи, **не измерение
общей точности модели**. Масса неизвестна: возвращённые граммы — предположение,
их точность и КБЖУ эта проверка не подтверждает. На смешанном фото видны также
другие продукты и напиток; два заранее выбранных признака — рис и фасоль.
Допускается одно составное название, совпадение не требует отдельных ингредиентов.
Остальные названия требуют ручного просмотра и не считаются эталоном рецепта.

По умолчанию выполняются только локальные проверки SHA256, размера и отсутствия
EXIF/ICC в JPEG. Приватная конфигурация не читается, сети и расходов нет:

```sh
python3 tool/check_photo_cases.py
```

Живой прогон требует явного выбора случаев, отдельного флага и файла подключения:

```sh
python3 tool/check_photo_cases.py --case banana --case mixed-rice-beans \
  --allow-live-request --private-config /private/build-config.json \
  --report build/photo-cases-live.json
```

Файл имеет прежние ключи `FITLIFE_PHOTO_SERVER` и `FITLIFE_PHOTO_TOKEN`; не
передавайте токен аргументом и не добавляйте конфигурацию в Git. Адрес ограничен
существующим Worker, путь `/v2/identify`. Максимум **два запроса за запуск**,
без повторов, перенаправлений, запасного провайдера и изменения квот. Любая ошибка
HTTP/контракта/распознавания останавливает оставшийся набор. Повторный ручной запуск
снова расходует квоту; не запускайте его для получения удобного результата.
Автоматический CI запускает только локальные unit-тесты с подставным HTTP.

Отчёт содержит SHA снимка, число попыток, время, только проверенные поля V2:
название, предполагаемые граммы, категорию уверенности и коды предупреждений.
Неизвестные поля, в том числе калории/БЖУ/источники от модели, отклоняются; сырые
ответы/токены/изображения/тексты исключений не выводятся. В корректном ответе должны
найтись заранее заданные названия категорий. Это грубая проверка узнаваемости,
не статистический тест. Ошибка остаётся ошибкой; ожидаемые категории нельзя менять
по полученному ответу. Этот инструмент сам не выбирает источник питания, не
меняет дневник или настройки приложения и не заменяет проверку Android-интерфейса.

Пользовательский путь остаётся: фото → названия/предположение о порции → выбранный
пользователем источник → Nutrition Engine → подтверждение → запись. Проверка
галереи/согласия без облака и отдельный живой Android-путь с яблоком сохранены.
Более разнообразные блюда и физический телефон остаются отдельной приёмкой.

Источники, авторство, SHA256 и подготовка: [tool/fixtures/README.md](tool/fixtures/README.md).
